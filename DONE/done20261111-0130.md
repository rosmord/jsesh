# SVG sign embedding

created
: 20261028

closed
: 20261111

Add the possibility to embed user-made SVG signs in a document.

- the sign SVG will be stored in the document header;
- the svg will be encoded in base64
- Embedded sign names will be "sign1, sign2, ..."
- a document header will also contain the maxembeddedsignid value as soon as there is at least one embedded sign in the document.
- if an embedded sign is deleted, the maxembeddedsignid will not be decremented, so that the next embedded sign will have a new name.
- the user will be able to state that the sign is a variant of a given Gardiner code, and perhaps to write a small description - which will also be stored in BASE64
- if the user has associated a sign with a Gardiner code, searches for this code will find the sign (in the possibilitylist)
- a small window can be opened to show text-specific signs, allowing the user to select them, see their code, and possibly edit their description.
- when editing the text:
  - the possibility list for the Gardiner code will include the user-made sign,
  - the codes will given by the system will be short and easy to type
- an export menu will allow to get individual SVG files for the user-made signs, for possible addition in regular fonts.

Copy/paste to other MDC texts:

If segment of text containing an embedded sign is pasted as :

- a picture, there is no problem. The embedded MdC, if any, will be copied with the sign in its header
- a MdC text : for "copy as mdc", the text will be copied as typed. It's the responsability of the user to edit it if needed to avoid problems
- from JSesh to JSesh
  - in the same document, no problem
  - in another document, the copy might be a bit more complex, as it should be a more complex object than a simple HieroglyphicText - it would contain the list of embedded signs, and the system will a) need to add them to the target text, and b) to replace the embedded sign in the text by a reference to the new embedded sign in the target text. The system will also need to check if the embedded sign has not already been copied (which can be done by comparing the base64 encoding of the sign). We don't expect texts to contain a huge number of specific signs.

## Status (2026-11-10)

Done (see the developer journal, "Signs embedded in a document"):

- model, header (`JSesh_embedded_sign_sign<n>`, `JSesh_max_embedded_sign_id`, format version `v0` in each sign line), original SVG file (base64) with a rendering cache for the JS port (base64), description in base64;
- drawing, possibility lists (variant of a Gardiner code), exports keeping the signs in their embedded MdC;
- UI: add from SVG, modal list of the text's signs (insert, edit, remove with a warning, export), File > Export as SVG;
- JS port: reading, writing and drawing.
- copy/paste between two JSesh documents (2026-11-10): the copied text carries the signs it uses (`JSeshFragment`, sent instead of `ListOfTopItems` only when there are some); on paste, a sign with the same SVG is reused, the others get new numbers, and the codes of the pasted text are renamed.
