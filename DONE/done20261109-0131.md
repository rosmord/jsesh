## Summary

We want to be able to align parts of texts for different reasons:

1. in some cases, the text is aligned in the original document. The people of the Rosetta project gave examples of cartouches which are aligned (same starting point); so-called “crossword puzzle” inscriptions also come to mind.
2. in critical editions, we want to align the various variants. This was a use of the *Manuel de Codage* from an early stage, with the publication of Dirk van der Plas, “L'hymne à la crue du Nil”.

In contrast with what happens with regular word processors, those tabs are anchored to the text, not to the global page.

For instance, if we have two lines with tabs:

~~~text
a text       <TAB> continued
another text <TAB> continued
~~~

The actual position of the tab stop will be fixed by the longest text before it.

- tab stops are local to a `%zone`;
- tab stops are dynamic (as in a LaTeX `tabular`): they move to accommodate the length of the text between them. The idea is that they can be used for critical editions;
- tab stops are introduced by a special `%tab` operator;
- they work in line and in column layout.

## Similar systems

### TeX/LaTeX

For a computer scientist, this situation reminds one of the way TeX/LaTeX handles tabbing.
In fact, I did use this with my [HieroTeX](https://hierotex.qenherkhopeshef.org/) system.

In LaTeX, tab stops cut lines into fields. They are anchored to the environment (the left margin of the block), not to the page.

The two important commands are `\=` to define a tab stop, and `\>` to jump to the next tab stop. This being said, the tab stops are not dynamic: they are defined when they are met. So LaTeX generally uses a fake line with the maximal length of each section, cleared by a `\kill` command.

Typical use:

~~~latex
\begin{tabbing}
The Variant A \= is indeed a really \= long text \\   % ruler line: defines three stops, not printed
Variant A \> is a really  \> short example.\\
Variant C \> reads \> a much longer reading here.\\
\end{tabbing}
~~~

Result:

~~~text
The Variant A is          long text
Variant A     is a really short example.
Variant C     reads       a much longer reading here.
~~~

We don't want that.

In fact, we would like the behaviour of the `tabular` environment, which:

- is dynamically defined (the size of the largest area is used);
- allows for specific alignment of each column (left, right, center, justified).

### Mark-Jan Nederhof PhilologEg

Mark-Jan Nederhof has developed an extensive system dedicated to text edition and alignment [ref](https://sites.cs.st-andrews.ac.uk/people/mn31/egyptian/align/). It's perhaps a bit too complex for us currently.

In PhilologEg, the layout is mostly automatic, from anchor points. The line breaking is also computed. We probably prefer a more direct control for an interactive word processor.

### MacScribe

The latest versions of MacScribe had a simple tabbing system, which is not compatible with alignment of text. It has a single `%` operator, which defines the tab stops. The text aligns at tab stops.

## Specification

### Syntax

~~~text
%tab
%tab[n=3,align=end]
~~~

`%tab` is a top item, separated from its neighbours by `-`, like `?N`.

`n` (optional)
: the **absolute** index of the tab stop, ≥ 1. By default, the index of the previous `%tab` in the line, plus 1. Indexes in a line must be strictly increasing; a wrong index is treated as “previous + 1”, with a logged warning.

`align` (optional)
: the alignment of the **cell before the tab**, with the values of the line alignment: `start` (default), `end`, `center`, `justify`. `justify` spreads the free space between the units of the cell.

Tab stop 0 is virtual: it is the start of the line, and is never written.

### Vocabulary

tab stop
: a computed position, number *i*, shared by all lines of the zone.

tab cell
: the text of one line between two tabs (or between the start of the line and the first tab, or between the last tab and the end of the line). A cell may span several tab stops, when indexes are skipped.

tab column
: the interval between two consecutive tab stops.

tab scope
: the set of lines whose tab stops are shared: the content of a zone.

The existing Winglyph `?N` (`TabStop` in the model) is renamed **absolute tab** (`AbsoluteTab`); the new `%tab` is `Tab`.

### Example

~~~text
my line 1 -%tab- middle of text -%tab- end of text
line 2 -%tab- yep -%tab[n=3]- the end of the second line
the third line has a long start before tab 2 -%tab[n=2]- middle of text -%tab- third
~~~

Gives:

~~~text
<0>        <1>                                <2>             <3>
my line 1  middle of text                     end of text
line 2     yep                                                the end of the second line
the third line has a long start before tab 2  middle of text  third
~~~

Of course, this example is not correct *Manuel de Codage*, but it illustrates the idea (with a gap of two characters). Stop 1 is fixed by the first cells of lines 1 and 2. The first cell of line 3 spans columns 0 and 1, so it pushes stop 2, not stop 1. The cell “yep” of line 2 spans columns 1 and 2.

Having a `%tab[n=3]` as the only tab in a zone is correct. It defines tab stop 3, and implicitly tab stops 1 and 2. It might be useful if we plan to add those tab stops later.

### Last cell

The cell after the last tab of a line takes the alignment of the line (the `align` of the `!`/`!!` which ends it). It is aligned in `[tabPos[last], R]`, where `R` is the maximal line width (`maxLineWidth()`) if the zone has a width, and otherwise the width of the longest line of the zone (the same rule as for line alignment).

As each tab gives the alignment of the cell before it, and the line gives the alignment of the last cell, all combinations of alignments are possible, and there is no need for an explicit tab at the start of the line.

Consequence: one can't stretch a whole table to the width of the zone, except through its last cell.

### Spacing

By default, the space between two tab columns is the usual gap between quadrats. It can be changed with `%zone[tabgap=N]` (in % of a quadrat height, like the other zone lengths). A cell ending at stop *i* requires `tabPos[i] ≥ start + size + gap`; a skipped stop adds no gap.

### Scope

In the first version, tabs are active only in the content of a `%zone`. In the main text, `%tab` is read and written, but ignored by the layout (pagination, in particular in columns, makes things harder).

Lines without `%tab` are not affected: they keep their usual line alignment.

### Soft wraps

Lines with tabs can be soft-wrapped when the zone has a width. Only the tabs **before the first soft wrap** of the logical line are active; the following ones are ignored.

The wrap points are computed on the natural widths (a `%tab` counts as zero width); the tab stops are applied afterwards, to the first physical line only. If tabbing makes this line overflow, the overflow is accepted (no re-wrapping): the algorithm stays one-pass.

The last active cell ends at the wrap point. It takes the alignment of non-final physical lines (JUSTIFY stays JUSTIFY, START stays START).

### Winglyph `?` operator

Winglyph has an absolute tabbing system, using the `?` operator. JSesh handles it (it's used in the demonstration file), and it is kept. In a zone, a `?N` placed **after** a `%tab` in the same line is ignored by the layout (but kept in the model and written back); a `?N` before the first `%tab` keeps its effect inside the first cell (the layout is sequential, and doesn't know yet that a tab will follow).

### Zone sizes

If zones are used as tab containers, one might want to be able to force a zone to be a specific size, in particular to be as large as its parent. This is a separate mechanism (todo 0156, zone `fill`).

## Algorithm

We suppose a text in lines for ease of presentation; in columns, the same is done along y.

The layout is still done in one sequential pass (`LineAccumulator`). A `%tab` closes the current cell and records the boundary (tab index, alignment). In `endLayout()`, **before** the line alignment, a `TabLayout` class shared by `LineLayout` and `ColumnLayout`:

1. collects the cells `(startTab, endTab, naturalSize)` of the tabbed lines of the zone;
2. computes the tab stop positions:

   ~~~python
   tabPos = array of size [0..maxTabIndex]
   tabPos[0] = 0
   for tabIndex in [1 .. maxTabIndex]:
     # all cells which end AT tabIndex (can be pre-computed);
     # they start before tabIndex, so their start position is known
     computedPos = max(tabPos[cell.startTab] + cell.naturalSize + gap for cell in cellsEndingAt[tabIndex])
     tabPos[tabIndex] = max(tabPos[tabIndex-1], computedPos)
   ~~~

   A stop which no cell reaches gets the position of the previous one;
3. computes `R` (see “Last cell”);
4. moves each cell rigidly, according to its alignment, in `[tabPos[startTab], tabPos[endTab]]` (or `[tabPos[last], R]` for the last cell).

The line alignment (`alignLines`) then ignores the tabbed lines, as their alignment was applied to their last cell. The zone size is computed after that, so it needs no change.

Right-to-left text needs no special handling: the layout is computed left to right, and mirrored when drawing.

## GUI display

If *view tabs* is activated, tabs will be displayed in blue, with their index (and maybe an icon for their alignment). The tab display will be somehow at the top of the quadrats' height — with 0 official width, of course.
