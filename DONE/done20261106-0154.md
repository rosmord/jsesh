# Subcadrats should not automatically change layout

created
: 20261103

closed
: 20261106

Currently, `i-mn:n` and `i-(mn:n)` don't have the same rendering. It's a bit annoying.

In fact, we would like to be able to simplify `i-(mn:n)` to `i-mn:n` without changing the layout. We end up currently with absurd stuff like `i-((mn:n))`.

1. subquadrats should be syntactic features, not semantic. A subquadrat is needed to correctly group `n:(x:t)*nxt`, but in a group like `i-(mn:n)`, it should behave like a quadrat `i-mn:n`
2. when saving a text with **useless* subquadrats (not useful like `n:(x:t)*nxt`), the subquadrat level should be removed. Thus, 
   - `i-(mn:n)` should be saved as `i-mn:n`
   - `i-((mn:n))` should be saved as `i-mn:n`
   - `i-(((mn:n)))` should be saved as `i-mn:n`
3. This might change the aspect of some of the current texts, but it's worth it.

## Why the layouts differed

The model of `i-mn:n` and `i-(mn:n)` was not the same:

- `i-mn:n`: the second quadrat is `Cadrat[HBox[mn], HBox[n]]`, a stack laid out directly by the line.
- `i-(mn:n)`: the second quadrat is `Cadrat[HBox[SubCadrat(BasicItemList[Cadrat[HBox[mn], HBox[n]]])]]`.
  The stack was first laid out as a self-contained view (`Layout.visitSubCadrat`), and the outer quadrat then treated it as one opaque element of a row (`Layout.visitHBox`). That row-level processing (enlarging, `small skip`, and the `containsOnlyOneSign` shortcuts, which never apply to a `SubCadrat`) produced a different result.
- On top of that, `MdCModelWriter.visitSubCadrat` always wrote the parentheses, so they
  never went away (`i-((mn:n))`).

## What has changed

The sub-quadrat is now treated as syntax only: a *useless* one never reaches the model, and is never written.

- `jsesh.model.Cadrat.uselessSubCadratContent()` (new): if the quadrat has one row, whose only element is a `SubCadrat` whose list holds exactly one `Cadrat`, returns a copy of that inner quadrat (recursively, so `((mn:n))` and `(((mn:n)))` give `mn:n`). Shading: if both are shaded differently nothing is changed; if only the outer one is shaded, the shading is moved to the inner one.
- `jsesh.mdcreader.AstModelBuilder.visitCadrat`: pushes the simplified quadrat when there is one.
  `visitInsert` is untouched (its `SubCadrat`s are structural). The AST (`AstSubCadrat`) stays literal.
- `jsesh.io.mdc.MdCModelWriter.visitCadrat`: writes the simplified quadrat, so models built in the editor (e.g. `HBox.buildHorizontalListElement`) are saved without useless parentheses.
- Parentheses are kept when needed: `n:(x:t)*nxt`, `x*(a:b)`, `(i-w)`, `(a:b)^^w`.
- Tests: `MdCModelWriterSubCadratTest`. Glossary updated (Quadrat entry).

### Not done

- `Layout` is unchanged: a model edited in the editor keeps its wrapper in the display until
  it is saved and reloaded.
