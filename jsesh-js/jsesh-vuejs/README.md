# JSesh-vueJS

Vue 3 components for JSesh (`@jsesh/vue`), and a sample application.

The components are thin wrappers over the Web Components of `@jsesh/elements`, `@jsesh/editor` and `@jsesh/palette`: they
give them Vue props, `v-model` and events, and hide the details (property versus attribute, boolean attributes, event
names). All the behaviour stays in the JSesh packages.

| Component | Wraps | Use |
|---|---|---|
| `<JSeshText>` | `<jsesh-text>` | Displays MdC: `<JSeshText mdc="nfr-f:r" :cadrat-height="40" />` |
| `<JSeshEditor>` | `<jsesh-editor>` | The hieroglyphic editor: `<JSeshEditor v-model:mdc="text" />` |
| `<JSeshEditorToolbar>` | – | Undo, redo, stack / side by side / ligature, cartouche, red, for an editor. |
| `<JSeshPalette>` | `<jsesh-palette>` | The sign palette: `<JSeshPalette @sign-chosen="editor.insertSign($event)" />` |

`useExternalState(source)` turns the `subscribe` / `state` pair of the headless `EditorSession` and `PaletteController`
into a Vue `ref`, if you prefer to write the markup yourself (see `Documentation.md`, section *Vue and React*).

## Using it

```ts
// main.ts
import { JSeshPlugin } from "@jsesh/vue";
import { createApp } from "vue";
import App from "./App.vue";

createApp(App)
  .use(JSeshPlugin, { glyphsUrl: "/jsesh-glyphs/" }) // where the glyph data is served; always set it with a bundler
  .mount("#app");
```

The plugin calls `configureJSesh` and registers the four components globally. To import them where they are used
instead, call `configureJSesh({ glyphsUrl })` (also exported by `@jsesh/vue`) once, and
`import { JSeshEditor } from "@jsesh/vue"`.

```vue
<script setup lang="ts">
import { ref, useTemplateRef } from "vue";
import { JSeshEditor } from "@jsesh/vue";

const text = ref("nfr-f:r");
const editor = useTemplateRef<InstanceType<typeof JSeshEditor>>("editor");
</script>

<template>
  <JSeshEditorToolbar :editor="editor" />
  <JSeshEditor ref="editor" v-model:mdc="text" :cadrat-height="40" />
  <JSeshPalette @sign-chosen="editor?.insertSign($event)" />
  <JSeshText :mdc="text" />
</template>
```

If you compile `@jsesh/vue` from its sources (the `source` export condition, as the sample does in development),
tell the Vue compiler that `jsesh-*` tags are Web Components:
`vue({ template: { compilerOptions: { isCustomElement: (tag) => tag.startsWith("jsesh-") } } })`. The published `dist/` does
not need it.

### `<JSeshText>`

Props: `mdc` (required), `cadratHeight`, `direction` (`ltr`/`rtl`), `orientation` (`horizontal`/`vertical`), `centered`,
`justified`, `glyphsUrl`, `jseshStyle` (any style change, see `JSeshStyle` in `@jsesh/core`). Events: `render`, `error`.
An invalid text does not throw: it is shown as plain text and `error` is emitted, so it can follow a text field.

### `<JSeshEditor>`

`v-model:mdc` is the text as MdC. Typing updates it; changing it from outside replaces the editor's text. The editor
keeps its undo history across such replacements, so give it a `:key` (a document id) to start afresh on another text.

Props: `cadratHeight`, `direction`, `orientation`, `glyphsUrl`, `jseshStyle`. Events: `change` (the editor's
`EditorState`: cursor, selection, code being typed...), `error`.

Exposed (use a template ref): `insertSign(code)`, `insertMdc(mdc)`, `group(":" | "*" | "&")`, `cartouche()`, `toggleRed()`,
`undo()`, `redo()`, `document()` (the text as a JSesh `.gly` file), `focus()`, the reactive `state`, `session` (the
`EditorSession`) and `element` (the `<jsesh-editor>`). Appearance: CSS custom properties and `::part(surface)`, as for
`<jsesh-editor>`.

### `<JSeshEditorToolbar>`

Props: `editor` (the template ref of a `JSeshEditor`), `labels` (translations: `undo`, `redo`, `stack`, `sideBySide`,
`ligature`, `cartouche`, `red`). The default slot adds your own buttons. It renders plain `<button>`s in a
`div.jsesh-toolbar`: style them in your CSS.

### `<JSeshPalette>`

Props: `glyphsUrl`, `labels`, `storage`, `database` (see `<jsesh-palette>`). Event: `sign-chosen` (the code), `error`.
The palette is built again each time `labels`, `storage` or `database` change, so pass stable values.

## Sample application

`sample/` is a small notebook of hieroglyphic texts (kept in the browser's `localStorage`): a list of texts with
thumbnails (`JSeshText`), an editor with its toolbar and the palette, a raw MdC field which follows the editor (and
flags invalid MdC), a preview with size, direction and orientation, and a download of the text as a `.gly` file.

```bash
cd ..                  # jsesh-js
npm install            # the two packages here are workspaces of jsesh-js
npm run build          # once: the @jsesh/* packages
cd jsesh-vuejs/sample
npm run dev            # http://localhost:5173/
```

The glyph data comes from `../../packages/glyphs/data` (generated by `./gradlew :jseshJsExport:exportAll`, see
`jsesh-js/README.md`): `vite.config.ts` serves it under `/glyph-data/` and copies it into `dist/` when building. In
your own project, copy the data into `public/` instead (or serve it from anywhere) and give its URL to `JSeshPlugin`.

Files: `src/main.ts` (plugin), `src/App.vue` (layout, wiring between editor, toolbar and palette), `src/documents.ts`
(the stored list), `src/components/DocumentList.vue`, `src/components/MdcField.vue`.

## Building the library

```bash
cd jsesh-vuejs
npm run build     # dist/jsesh-vue.js and the type declarations
npm run typecheck
```
