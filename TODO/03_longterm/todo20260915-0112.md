# Automated Sign Id Management

created
: 20260915

For databases, the possibility to link to a part of a text is quite useful. To do this, one needs a reference system. In paper publications, we use coordinates relative to anchors, classicaly to line or column numbers. However, this is not precise enough for computer databases. 

A simple solution is to use *relative* coordinates, e.g. "Louvre C14, line 4, quadrat 6 to line 5, quadrat 3.

However, those coordinates are fragile and can be broken by subsequent editions and fixes.

To avoid this problem, one can give identifiers to elements in the text - for instance to signs. The Manuel de Codage, as understood by JSesh, can be used in this way. A1\id320 would be "sign A1, with id 320".

To do this, one needs an automated system which will ensure that:

1. ids are unique (in a given text, only one sign has a given id);
2. ids are not reused (if part of a text is gone, it's gone and its ids are not used again);
3. pasted text should get new ids;
4. simple editions (breaking a group, rearranging signs...) should preserve ids.

It's not overly complex, but it requires some work.

I think that if I code this functionality:

- it will be activated on individual documents (in the document property)
- texts with automated ids will get a JSesh-maxid: entry in their header
- the start of the text will get an implicit "0" id.

Source: https://github.com/rosmord/jsesh/issues/60 (issue #60)
