# Simplify the Layout class

The `Layout` class hierarchy has only one implementation, so it should
probably be flattened. That would also help clarify its relationship with
the drawing preferences.

- [ ] remove the `depth` field in `Layout`; hide `Layout` altogether if
      possible;
- [ ] once the new version is functional, think about the lifecycle of
      `Layout` objects. They should probably be simplified into short-lived
      objects;
- [ ] more generally, reduce the unnecessary pluggability of the various
      "experts" (Layout/Drawing, etc.). There is probably no real need to be
      able to swap the drawing system at runtime.
