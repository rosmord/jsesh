# Improve ergonomics of editing inside nested structures

created
: 20260726

Editing inside structures has an ergonomics problem.

It would be also nice to be able to navigate in **groups** of signs with the cursor. This is a function which existed in tksesh, BTW, and has been planed for JSesh almost since the beginning. The idea is to code positions, not as a simple integer, but as a stack/list of integers.

## Status (2026-10-19)

First step done: the cursor can move *inside* quadrats (navigation and display only).

- `CaretGranularity` (`QUADRAT` / `INNER`) is a per-editor setting (`JMDCEditorWorkflow.setCaretGranularity`),
  toggled by the *Move Cursor Inside Quadrats* action (Edit menu, `shortcut shift Q`), remembered in the user preferences.
- `PositionNavigator` lists the stops: interior gaps between the rows of a quadrat, between the elements of a row,
  between the signs of a ligature or the parts of a complex ligature. Cartouches and sub-quadrats are entered too (both edges of their content are stops).
  Absolute groups are navigable too (stops between their signs). Hieroglyphs and overwrites are atomic for now.
- `MDCMark` = top-level anchor + inner tail; `MDCCaret.getInsertPosition()` etc. stay top-level (snapped to the position before the quadrat),
  `getInsertExactPosition()` is the exact one. Every edit moves the caret back to the top level.

Still to do:

The cursor stays inside the quadrat.
