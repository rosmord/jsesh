# Simplifies the use of MDCPosition

created
: 20200622

- [x] The model for the text should have a better name;
- [x] MDCPosition should not depend on the text it links to. It should be a simple value object.
- [x] It should be systematically used instead of int in the API, wherever an int
  stands for a *position in the text* (a point between two top items):
  insertion points, range limits (start/end of a selection, of a line, of a
  page...), cursor and mark locations, search hits.

  Ints which should **stay** ints:

  - **factories and the escape hatch:** `new MDCPosition(int)`,
    `HieroglyphicText.getPositionAt(int)`, `HieroglyphicTextModel.buildPosition(int)`,
    and `MDCPosition.getIndex()` for low-level code;
  - **offsets** (a number of steps, not a place): `MDCCaret.moveInsertBy(int)`,
    `HieroglyphicText.getNextPosition(MDCPosition, int)`,
    `MDCPosition.getPreviousPosition(int)`...;
  - **element indexes**, which number the top items themselves rather than
    the gaps between them: `HieroglyphicText.getTopItemAt(int)`,
    `removeTopItem(int)`, `getChildAt(int)`...;
  - **code working on the children of any `ModelElement`** (cadrats,
    cartouches... not only the top-level text), since `MDCPosition` is
    currently top-level only: the model operations (`Insertion`, `Deletion`,
    `Replacement`, `ZoneModification`), `ViewBuilder.buildView(ModelElement, int, int)`,
    `MDCView.addAt/remove`, `AlphabeticRuns`. They can only switch to
    positions with the next item (tree positions).
- [ ] Redefine `MDCPosition` so that it can point to anywhere in the text, not just quadrat limits.
