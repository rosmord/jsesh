# Ensure JSesh components can be used in headless mode

created
: 20261002

Currently, JSesh components (like JMDCEditor) cannot be used in headless mode, which is annoying for automated testing.
They register keyboard shortcuts for actions like cut, copy, paste, and undo, which requires access to the toolkit to determine the appropriate modifier key (Cmd/Ctrl). In headless mode, the toolkit is not available, leading to failures.

- [ ] isolate the use of `Toolkit.getDefaultToolkit()`;
- [ ] introduce helper classes doing something like:
  
  ~~~java
  static int getShortcutMask() {
    if (GraphicsEnvironment.isHeadless()) {
        return PlatformDetection.getPlatform() == PlatformDetection.MACOSX
            ? InputEvent.META_DOWN_MASK : InputEvent.CTRL_DOWN_MASK;
    }
    return Toolkit.getDefaultToolkit().getMenuShortcutKeyMaskEx();
   }
  ~~~

Another possibility would be to use plain platform detection, as there are only two real possibilities there: Mac vs. the rest of the world.
