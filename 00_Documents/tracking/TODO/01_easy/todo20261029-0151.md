# Add a sign order indicator to `%insert`

created
: 20261029

In `%insert[dir=bs](A,B)`, the sign order follows the Unicode convention:
the first argument `A` is the target (the sign the group is inserted into),
and the second argument `B` is the inserted group.

This is a problem for linguistic processing, because the order of the
arguments is then not always the reading order.

## Proposal

Add an option `target`, which says which argument is the target:

- `target=1` (default): the first argument is the target. This is the current
  behaviour, so existing texts are unchanged.
- `target=2`: the second argument is the target.

The arguments are then **always** in reading order: first argument, then
second argument.

```
%insert[dir=bs](A,B)          A is the target, B is inserted (= target=1)
%insert[dir=bs,target=2](B,A)   A is the target, B is inserted, B is read first
```

The values are numbers, not `before`/`after` or `left`/`right`, because
those words depend on the writing direction.

`dir`, `dw` and `dh` always apply to the **target**, whichever argument it
is. In `%insert[dir=bs,target=2](B,A)`, `B` is placed in the bottom-start
corner of `A`.

## Places to update

- parser (`MDCParser`, `AstInsert`) and `AstModelBuilder`
- model (`Insert`): store which argument is the target
- `MdCModelWriter`: write `target=2` only when it isn't the default
- layout: place the inserted group according to the target, not the
  argument position
- editor actions that build inserts (`JMDCEditorWorkflow`)
- JS port (`jsesh-js`), its fixtures, and `user-guide.md`
