# Tabbing support

## Summary

We want to be able to align parts of texts for different reasons:

1. in some cases, the text is aligned in the original document. The people of the Rosette project, gave examples of cartouches which are aligned (same starting point) ; so-called “crossword puzzle” inscription also come to mind.
2. in critical editions, we want to align the various variants. This was a use of the *Manuel de Codage* from an early stage, with the publication of  Dirk van der Plas, “L'hymne à la crue du Nil”.

In contrast with what happens with regular word processors, those tabs are anchored to the text, not to the global page.

For instance, if we have two lines with tabs:

~~~text
a text       <TAB0> continued
another text <TAB0> continued 
~~~

The actual position of the tab stop will be fixed by the longest text before it.

Add support for tabbing, in the TeX/LaTeX way.

- tabbings should allow one to define tab stops
- tab stops would be local to a %zone
- tab stops will dynamic (as in LaTex). I.e. they will move to acccomodate the length of the text between them. The idea is that the can be used for critical editions.
- tab stops will be defined by using special operatators; we need to think about them
- they will work in line or in column layout.

## Similar systems

### Tex/Latex

For a computer scientist, this situation reminds one of the way TeX/LaTeX handles tabbing.
In fact, I did use this with my [HieroTeX](https://hierotex.qenherkhopeshef.org/) system.

In LateX, tab stops cut lines into fields. They are  are anchored to the environment (the left margin of the block), not to the page.

The two important commands are `\=` to define a tab stop, and `\>` to jump to the next tab stop. This being said, the tab stops are not dynamic: they are defined when they are met. So LaTeX generally uses a fake like with the maximal length of each section, cleared by a `\kill` command.

Typical use:

~~~latex
\begin{tabbing}
The Variant A \= is indeed a really \= long text \\   % ruler line: defines three stops, not printed
Variant A \> is a really  \> short example.\\
Variant C \> reads \> a much longer reading here.\\
\end{tabbing}
~~~

Result:

~~~text
The Variant A is          long text
Variant A     is a really short example.
Variant C     reads       a much longer reading here.
~~~

We don't want that.

In fact, we would like the behaviour of the `tabular` environment, which:

- is dynamically defined (the size of the largest area is used) ;
- allows for specific alignment of each column (left, right, center, justified).


### Mark-Jan Nederhof PhilologEg

Mark-Jan Nederhof has developped an extensive system dedicated to text edition and alignement [ref](https://sites.cs.st-andrews.ac.uk/people/mn31/egyptian/align/). It's perhaps a bit too complex for us currently.

In PhilologEg, the layout is mostly automatic, from anchor points. The line breaking is also computed. We probably prefer a more direct control for an interactive word processor.

### Macscribe

The latest versions of Macscribed had a simple tabbing system, which is not compatible with alignment of text. It has a single `%` operator, which defines the tab stops. The text align at tab stops.

## Ideas for JSesh

The basic idea is similar to the Macscribe system:

- tab stops position depend on the text;
- they are dynamic.

JSesh tabs will be **scoped**. A tab will be valid in a **zone**, or perhaps in a **page**.

We want to be able to "skip" a tab. i.e., to do stuff like:

~~~text
my line 1 <TAB0> middle of text <TAB1> end of text
line 2 <TAB0> yep <TAB2> the end of the second line
the third line has a long start before tab1 <TAB1> middle of text <TAB2> third
~~~

Would give us:

~~~text
                   <TAB1>                      <TAB2>         <TAB3>
my line 1          middle of text              end of text
line 2             yep                                        the end of the second line
the third line has a long start before tab1    middle of text end of text
~~~

- Tabbing should work also vertically ;
- tabbing should have an optional justification ?

## Syntax

~~~text
%tab[skip=1,justification=fill]
~~~

Justification would concern the zone **after** the tab. To use justification **before** a tab, one would introduce a tab at the beginning of the line. In case of tabbing, a virtual tab 0 is supposed to stand at the beginning of the line, with a justification of `start`. If another justification is needed, an explicit tab can be added at the beginning of the line by the user.

In a line (or column), the first explicit tab would be tab 1, the second tab would be tab 2, etc. The optional `skip` parameter would allow to skip a tab stop.

Thus the example above would be something like:

~~~text
<TAB0>             <TAB1>                      <TAB2>             <TAB3>
my line 1          %tab middle of text         %tab  end of text
line 2             %tab yep                                       %tab[skip=1] the end of the second line
the third line has a long start before tab1   %tab[skip=1] middle of text end of text
~~~

Of course, this example is not correct *Manuel de Codage*, but it attempts to illustrate the idea.

Note that having, for instance, a `%tab[skip=3]`  as the unique tag in a zone would be correct. This would define tab stop 3, and implicitly tab stops 0, 1 and 2. It might be necessary if we plan to add those tab stops later.

## Algorithm

A point which might be tricky: tab stop skips. How do we handle a text between tab 0 and tab 2, for instance?

### Case one: we ignore the alignment of text

We suppose a text in lines for ease of presentation.

When a tab is met in a zone, we need to compute the layout on **each line which contains a tab**.

1. the beginning of line is implicitly tab0.
2. the system will collect the *minimal* size for each part of each tabbed line.

   a line segment (in the layout) might be something like: (startTab, endTab, minimalSize);

The algorithm:

~~~python
segments = [...] # all segments found in the zone
tabPos= array of size [0..maxTabIndex]
tabPos[0] = 0
for tabIndex in [1 .. maxTabIndex]:
  # find all segments which end AT tabIndex
  segmentsEndingAtTab = ... # can be pre-computed
  # the start position of those segments is known
  # we can compute their minimal end position
  computedPos = max(startPos(segment) + segment.minimalSize for segment in segmentsEndingAtTab)
  tabPos[tabIndex] = max(tabPos[tabIndex-1], computedPos)
~~~

- with `startPos(segment)` being the position of the start tab of the segment, which is known at this point.

Then:

- layout each segment, using the alignment of the segment (`start`, `end`, `center`, `fill`);

## Interaction with Line justification

tabs can work only if all tabbed lines have the same justification. Basically, we can handle:

- `start` : the tabbing works more or less naturally
- `justify` : see below.

If **one** line in the tabbed lines is justified, the tab is handled as justified.

For justified lines:

let's define the concept of tabbing cell. A tabbing cell is the text between two tabs, and between the last tab and the end of the line.

- we compute the tab positions (before justification, as tabbing can produce larger lines)
- we compute the largest line length
- we distribute the extra space between the tabbing cells, proportionally to their "natural size". I.e. a cell with width 0 will not be enlarged. If S is the sum of the natural sizes of all tabbing cells, and L is the largest line length, a cell with natural size s will be enlarged to $s + (L-S)(s/S)$.
- then the layout of views corresponding to each cell can be computed.
